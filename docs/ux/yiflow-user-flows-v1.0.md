# Yiflow User Flows v1.0

任务编号：YF-P1-002
状态：Completed
输出文件：docs/ux/yiflow-user-flows-v1.0.md
依据：Yiflow MVP Scope v1.0、Yiflow PRD v1.3、Implementation Plan v1.0

---

## 1. 文档目的

本文档定义 Yiflow MVP 阶段的核心用户任务流。

它不是视觉设计稿，也不是技术实现方案。

目标是明确：

- 用户在什么场景下使用 Yiflow。
- 用户输入什么。
- 系统执行什么动作。
- 成功状态是什么。
- 失败状态如何处理。
- 哪些行为不属于 MVP。

本文档是后续编辑器交互规格、Operation Protocol、CLI Design、Preview Design 的上游输入。

---

## 2. 用户角色

### 2.1 Product Manager / Business Analyst

主要目标：

- 把业务流程写成结构化流程图。
- 在 PRD、需求评审、方案讨论中使用。
- 快速修改节点、职责、异常分支。

### 2.2 Engineer

主要目标：

- 看懂业务流程结构。
- 基于 DSL / AST / validation 进行实现或校验。
- 避免流程图和真实逻辑不一致。

### 2.3 QA / Operations

主要目标：

- 理解主路径、异常路径和人工处理路径。
- 找到测试场景、边界条件和回跳逻辑。
- 将流程图用于测试用例或运营 SOP。

---

## 3. MVP 核心任务流总览

MVP 必须覆盖以下 5 条用户任务流：

| ID | 用户任务 | MVP 阶段 | 核心目标 |
|---|---|---|---|
| UF-001 | 首次出图 | P0/P1 | 从 DSL 生成可读泳道流程图 |
| UF-002 | 小改节点 | P1 | 修改文案、插入步骤、删除步骤 |
| UF-003 | 改职责归属 | P1 | 将节点移动到其他泳道 |
| UF-004 | 局部整理 | P1 | 对局部分支重新布局，不破坏主路径 |
| UF-005 | 导出进文档 | P1 | 将流程图用于 PRD / Markdown / Review 文档 |

P2 才处理自然语言生成和 AI 自动修改，因此本文档不把 NL → DSL / NL → Operation 作为 MVP 必做任务流。

---

## 4. UF-001：首次出图

### 4.1 场景

用户已经有一个业务流程，想快速生成一张结构化泳道流程图。

典型例子：

- 审批流程。
- 系统 + 人工混合流程。
- 异常 / 回跳流程。

### 4.2 用户输入

用户提供 `.swimflow.yaml` 文件。

输入至少包含：

- diagram 信息。
- lanes。
- nodes。
- edges。
- path_type。

### 4.3 系统动作

系统执行：

```text
读取 .swimflow.yaml
→ 解析为 Graph AST
→ 执行结构校验
→ 自动布局
→ 渲染 SVG / HTML Preview
```

### 4.4 成功状态

- 用户可以看到一张可读的泳道流程图。
- 泳道明确。
- 主路径从左到右清晰展示。
- 异常路径与回跳路径不会破坏主路径。
- SVG 可打开并用于文档。

### 4.5 失败状态

| 失败原因 | 系统反馈 |
|---|---|
| YAML 格式错误 | 提示解析失败和大致位置 |
| node id 重复 | 标出重复节点 id |
| edge 引用不存在 | 标出失效的 from / to |
| lane 不存在 | 标出不存在的 lane id |
| decision 出边不足 | 提示 decision 至少需要两个出口 |

### 4.6 不做

- 不支持自由画布拖拽。
- 不支持直接从自然语言生成图。
- 不支持导入 draw.io。
- 不承诺 Mermaid 高保真导入。

---

## 5. UF-002：小改节点

### 5.1 场景

用户在评审过程中发现流程需要轻微调整。

典型修改：

- 改一个节点文案。
- 在某个节点后插入一步。
- 删除一个多余节点。
- 修改一条边的 label。

### 5.2 用户输入

用户在编辑器中选择目标节点或边，然后执行操作：

- Edit text。
- Insert after。
- Insert between。
- Delete node。
- Edit edge label。

### 5.3 系统动作

系统执行：

```text
识别目标节点 / 边
→ 生成结构化 operation
→ 校验 operation 合法性
→ 应用到 Graph AST
→ 更新 DSL
→ 局部重排
→ 重新渲染
```

### 5.4 成功状态

- 被修改的节点或边正确更新。
- DSL 与画面保持一致。
- 主路径不被意外重写。
- 其他无关分支不受影响。

### 5.5 失败状态

| 失败原因 | 系统反馈 |
|---|---|
| 目标节点不存在 | 提示节点不存在，操作取消 |
| 删除节点会断开主路径 | 提示影响范围，要求用户确认或改用替代操作 |
| 插入节点缺少 lane | 提示必须选择 lane |
| 修改后校验失败 | 不保存变更，展示校验错误 |

### 5.6 不做

- 不支持一次性重写整张图作为默认修改方式。
- 不支持 AI 自动判断并修改，P2 再做。
- 不支持复杂批量编辑。

## 6. UF-003：改职责归属

### 6.1 场景

用户发现某个步骤的责任方不对，需要把节点移动到另一个泳道。

示例：

- “人工复核”从系统泳道移动到运营泳道。
- “通知用户”从后端泳道移动到前端泳道。
- “风险复核”从审核人泳道移动到风控泳道。

### 6.2 用户输入

用户选择节点，并执行：

```text
Move to lane: target_lane_id
```

或在编辑器中将节点拖到目标泳道。

### 6.3 系统动作

系统执行：

```text
校验目标 lane 是否存在
→ 更新 node.lane
→ 检查相关边是否仍可布局
→ 局部重排相关区域
→ 更新 DSL
→ 重新渲染
```

### 6.4 成功状态

- 节点归属到新泳道。
- 连线仍然可读。
- 主路径顺序不被改变。
- DSL 中该节点的 lane 字段正确更新。

### 6.5 失败状态

| 失败原因 | 系统反馈 |
|---|---|
| target lane 不存在 | 提示目标泳道不存在 |
| 节点被锁定 | 提示该节点不可移动 |
| 移动导致布局冲突 | 保留数据修改，但提示需要局部整理，或取消操作 |
| 操作会破坏主路径锁定 | 提示影响范围，要求确认 |

### 6.6 不做

- 不允许自由拖到任意坐标。
- 拖拽只改变 lane，不直接保存绝对坐标为真相。
- 不支持复杂组织权限判断。

## 7. UF-004：局部整理

### 7.1 场景

用户修改流程后，局部区域变乱，但不希望全图重新排版。

典型情况：

- 增加了异常分支。
- 增加了补件回跳。
- 移动了节点职责归属。
- 删除节点后连线变密。

### 7.2 用户输入

用户选择：

- 一个节点。
- 一条边。
- 一个分支。
- 一个泳道局部区域。

然后执行：

```text
Local relayout
```

### 7.3 系统动作

系统执行：

```text
确定局部影响范围
→ 识别锁定对象
→ 对局部节点重新计算布局
→ 避让主路径和锁定节点
→ 更新 layout 派生结果
→ 重新渲染
```

### 7.4 成功状态

- 目标区域更清晰。
- 主路径不被破坏。
- 锁定节点不移动。
- 异常路径和回跳路径更容易辨认。

### 7.5 失败状态

| 失败原因 | 系统反馈 |
|---|---|
| 局部范围无法识别 | 提示用户选择更明确的节点或分支 |
| 锁定对象过多 | 提示无法充分整理，建议解除部分锁定 |
| 布局结果不优 | 保留原布局，提示用户可尝试全图整理 |

### 7.6 不做

- 不做像 Figma/draw.io 那样的自由排版。
- 不允许局部整理改变流程语义。
- 不允许 renderer 直接成为数据真相。

## 8. UF-005：导出进文档

### 8.1 场景

用户希望把流程图放入 PRD、Markdown、评审材料或内部文档。

### 8.2 用户输入

用户选择导出方式：

- SVG。
- PNG。
- HTML Preview。
- Markdown 代码块预览。

### 8.3 系统动作

系统执行：

```text
读取当前 Graph AST / layout result
→ 渲染目标格式
→ 输出文件或预览内容
→ 保留 DSL 作为源文件
```

### 8.4 成功状态

- SVG 可在浏览器打开。
- PNG 清晰可插入飞书 / Notion / PRD。
- Markdown 预览可展示流程图。
- DSL 文件仍是可维护源文件。

### 8.5 失败状态

| 失败原因 | 系统反馈 |
|---|---|
| 当前 DSL 校验失败 | 阻止导出，提示先修复错误 |
| 图片尺寸过大 | 提示缩放或拆分流程 |
| 导出路径不可写 | 提示路径权限问题 |
| Markdown Preview 不支持交互 | 提示使用 Open in Yiflow Editor |

### 8.6 不做

- 不把 PNG/SVG 当作可编辑真相。
- 不支持云端发布。
- 不支持多人协作编辑。

| 用户任务流 | 关联能力 | 阶段 |
|---|---|---|

## 10. 非 MVP 用户流

以下用户流暂不进入 MVP：

| 用户流 | 原因 |
|---|---|
| 自然语言直接生成流程图 | P2 才做 NL → DSL |
| AI 自动根据一句话改图 | P2 才做 NL → Operation |
| 多人实时协作 | 超出 MVP |
| 自由画布设计 | 与 Yiflow 结构化定位冲突 |
| draw.io 导入导出 | 非 MVP 必需 |
| BPMN 完整建模 | 过重，不符合轻量工作流目标 |
| 流程执行 / 审批流运行 | Yiflow 只表达流程，不执行流程 |
